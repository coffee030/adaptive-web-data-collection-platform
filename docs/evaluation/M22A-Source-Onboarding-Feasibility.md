### Public HTTPS contract and reusable checks

- Public collection accepts a keyword of 1–128 printable characters after trimming. `initial_input` builds a GET to the saved origin and bare absolute path, with exactly one fixed query key (1–64 ASCII letters, digits, underscore, dot or hyphen) and an encoded UTF-8 keyword. It cannot express a POST, JS execution, a required fixed companion parameter, or an arbitrary public URL as Preview input. Manual example URLs are evidence for constructing a keyword Profile. Check the supplied listing and detail before any fetch and require the keyword URL to reconstruct the supported query.
- `checked_url` validates lowercase DNS HTTPS on port 443, origin membership and segment-prefix scope. It strips fragments and rejects malformed or ambiguous paths. `_same_origin_link` additionally rejects cross-origin links even when another origin is listed. Search rows must select an element with exactly one matching `a[href]`; selectors can select the anchor itself with XPath. Detail item and field mappings yield candidates whose required fields and types are checked by ingestion. A valid string can still name the wrong thing. [M7 contract](../contracts/M7-controlled-website-collection.md)
- Before the first discovery request, reload and require the approved Source, validate the explicit URL with `checked_url` and initialize an operation-specific shared request budget. Reuse `capture_html` for scope, robots, HTML media type, status, challenge and redirect handling. Its current public entry requires a `SearchRequests` object configured with a `KeywordSearch`. That object charges each attempted outbound GET, shares the deadline, uses Redis `OriginRate`, refreshes access in the slot and uses vetted public DNS and pinned TLS. The first GET for an otherwise permitted entry is the exact same-origin `/robots.txt`, which is exempt from path prefixes. Normal pages are subject to robots before transfer. A robots redirect or unsupported response stops the operation.
- **M22B gap.** The blank editor has no discovery operation, independent request-budget configuration, form semantics or selector proposal. Extract a small internal budget/context constructor from `SearchRequests` so a pre-draft caller can reuse public transport and fail-closed checks without inventing a saved Profile. Pass one authorized, single-origin context through homepage, optional hop, listing and detail. Make every subsequent destination pass the same checks, including manual examples. Do not expose low-level fetch or accept browser/script-only flows within this slice. [Public adapter](../../backend/core/web_adapter.py) · [Rate controller](../../backend/core/origin_rate.py)

## Proposed M22B budget

Caps apply to a single pre-draft attempt for one approved origin. Enforce the stricter of the limits below and the applicable permission, existing Profile limits, and current robots/rate policy. A Source stores origin/path scope and pacing. Profile limits govern its actual checks and Job; if a reviewed limit already applies to the Source's onboarding, carry it into the pre-draft context. For a blank draft with no previously reviewed Profile cap, enforce the stated small onboarding defaults.

| Stage or resource | Maximum | Accounting |
| --- | ---: | --- |
| Robots | 1 GET | Exact same-origin `/robots.txt` before a permitted HTML request. Counters include the request and body. Keep the result within this attempt. |
| Entry and optional hop | 1 homepage + 1 hop | Inspect at most 20 candidate homepage links in document order and fetch at most one candidate link, on the same origin. A unique supported direct form costs no hop. Do not inspect link candidates recursively. |
| Keyword results and detail | 1 results page + 1 detail | One GET supplies the results listing. No pagination. Inspect at most 20 listing rows and their eligible links locally. Fetch one representative eligible detail; ambiguity, unsafe selectors or exceeding inspection caps leaves the draft unresolved. |
| Requests and concurrency per origin | 5 attempted GETs total, 1 in flight | Direct has at most 4, one-hop 5, manual examples 3. Share the one ledger and deadline across stages. Core reserves a slot before waiting for cooldown or resolving DNS. A late denial or deadline can use a slot without reaching transport. Zero redirects in all phases. A redirect response costs its request slot and bytes, and the target is never requested. |
| Response bodies | 512,000 bytes per response, 2,560,000 bytes total | Hard body cap applies to robots, HTML, redirects and error responses. Derived total is 5 × 512,000. These are application body bytes, excluding headers and protocol overhead. |
| Time and pacing | 2 s/request; 20 s overall; at least 2,000 ms completion-to-next-start | Use the larger of onboarding, Source and robots pacing. The smaller of the request timeout and remaining overall time covers DNS plus transfer. Redis lock and cooldown waits also consume overall time. Check the shared deadline before each fetch and bound local parsing by inputs and counts. No automatic retries. |

Direct at 2 s pacing with no prior contention: robots → homepage → search/list → detail. Four requests, at most 2,048,000 body bytes and 14 s from up to 8 s of request time plus 6 s of gaps. One-hop: robots → homepage → form page → search/list → detail. Five requests, 2,560,000 bytes and up to 18 s from 10 s of requests plus 8 s of gaps. These arithmetic examples exclude parsing and prior cooldown. Deadlines still apply. The count-only fixture replay verified four and five requests respectively. A three-request cap runs out immediately before the direct detail and before the one-hop search. Preflight the minimum remaining stages and offer examples before making a request that cannot lead to verification. A 15 s cap can also constrain the one-hop path at 2 s pacing. No cap goes up to make either case fit.

- **Unsupported input:** multiple plausible forms, POST, JS-only behavior or a query shape the contract cannot express. Ask for a permitted, reproducible results URL for the same keyword and a representative permitted detail URL. One fresh, explicitly started example-led attempt skips entry and hop and uses the same gates, counters and pacing. Verify the detail belongs to the representative results and that the URL and required values make sense. No suitable pair means stop.
- **Denied access:** pending/revoked Source, disallowed path or origin, robots refusal, unsafe public destination, explicit challenge or authorization block. Stop the denied path. An operator may later supply an independently permitted pair if the denial was limited to the entry URL. Access blocking applies to that origin until reviewed.
- **Exhausted budget:** no credit for another mandatory request or a deadline/size cap is reached. Report the stage and limit, with examples as a separately initiated option only if they fit the original limits. The `test_budget_exhausts_before_detail_with_three_request_cap` replay did not issue a detail request.
- **Transient network failure:** surface a timeout, transport/5xx, or `429` with its cooldown if applicable. Keep retry decisions explicit. Honor Redis cooldown and `Retry-After`. A rate-lock wait that exceeds available time is a budget stop; a rate-controller outage is a fail-closed service error.
- **Later Profile checks:** an operator's explicit Preview and Validate are separate existing bounded operations, each with its own robots fetch and Profile ledger. They share the same origin pacing and authorization. With no redirects each adds three outbound GETs, so a fully checked direct onboarding would total 10 and a one-hop onboarding 11 across the three explicit operations. The prototype must not call these automatically or reset its pre-draft ledger for extra samples. Subsequent Job and binding verification are separate.

## Manual comparator

**Operator card.** Using the already authorized Source in your assigned card, start the timer when you open the card, before inspecting the site. Open **Sources → [assigned Source] → Create draft**. Start in the blank editor. Use the permitted homepage and keyword in the card to find results. Use the browser and its DOM inspector to choose selectors for publication links, title and integer count. If blocked, request a permitted example pair and keep the timer running. Enter record type `publication`; add required `title` (Text) and `count` (Integer), and set `title` as identity. Use **Keyword search and detail pages**, the registered Source origin, search path/parameter and your listing/detail selectors. Under **Pagination and request limits**, set one detail, the assigned maximum request count and a two-second request timeout; leave the next-link empty. Select **Create draft**. Enter the **Sample keyword**, choose **Preview**, inspect the values, and choose **Validate sample**. If a correction is needed, **Save draft** then Preview and Validate the new revision. In **Approval review**, open **Approval references**, save the matching hash and passing report ID, enter an **Approver label**, check the explicit confirmation and select **Approve version**. Stop when the Dashboard shows **Approved** for that same version and hash. Include unsuccessful inspections, edits, retries and all waits. Stop at 15 minutes if unfinished and record the reason and evidence. Use the same limit in both arms.
