# M4 Windows Narrator acceptance

**Status NOT RUN.** Built-in Narrator was available locally. The user listens to the speech and operates the browser. Allow about 15 minutes and use Windows 11, Edge or Chrome, headphones or speakers, and the isolated CSV fixture. First check `/api/v1/health`, the localhost console, and local approval settings. If Source Authorisation is needed, follow the runbook's terminal instructions in the isolated environment. [Demo Runbook](../demo/M4-core-demo-runbook.md)

1. Press `Win+Ctrl+Enter` to start Narrator. Use `Tab` and `Shift+Tab` for actual keyboard focus and `Enter` or `Space` to act. Toggle Scan Mode with `Narrator+Space`. In Scan Mode, arrow keys read content. The default Narrator key is `Caps Lock` or `Insert`. Distinguish the reading cursor from keyboard focus. [Microsoft Narrator controls](https://support.microsoft.com/en-us/accessibility/windows/narrator/chapter-1-introducing-narrator) [Microsoft Scan Mode guide](https://support.microsoft.com/en-us/accessibility/windows/narrator/chapter-3-using-scan-mode)
2. Start in Collection Jobs. Activate **Skip to main content** by keyboard and check focus reaches main. Open **Sources → Create source** and check that main or the new page heading is announced after navigation. Record unexpected focus movement, invisible focus, or a keyboard trap.
3. Submit **Create source** empty. Check that speech identifies the error summary and fields you can correct. Follow a field link in the summary and confirm the field name, required state, and error are announced. Choose the CSV adapter. Enter **Source name**, **Permission reference**, and **Allowed dataset IDs** (`listings`). Submit and verify the registration result and Pending access can be read. After a trusted operator authorises it, reopen the page and verify Approved access.
4. Open **Create draft**. Check that **Record type**, Identity field, each field group, CSV header, and Add field are identifiable. Use the runbook mapping to create a Draft, edit Record type, and save. Listen for the save result or read it on the page. Validate with an erroneous CSV and then a clean sample. Verify that Validation failed and passed are distinguishable and that the recovery guidance is readable.
5. Find **Approval review** by keyboard. Listen for the **Approver label** explanation and the **I reviewed this report and confirm approval** checkbox. Enter the label and verify that the checkbox state is announced and submission is disabled when unchecked. Check it and select **Approve version**. Verify the approval result and Read only explanation.
6. In **New Collection Job**, inspect the Source and Profile selectors, paste the CSV fixture from the runbook, and submit. Keep Job Details visible. Record which Pending, Running, and Partial states are announced automatically, which require opening **Run overview**, and whether focus is retained through result updates. If the fixture runs too quickly, check `CLAIMED` in the event list. Record transitions you did not hear as “not observed”.
7. Open a record through **View job records**. Verify table headings, row context, and link names. Open Evidence Metadata from the record or **Capture evidence**. Check that the Evidence heading, checksum label, Source, and pinned Profile can be read and that the Job return works. Press `Win+Ctrl+Enter` to close Narrator.

For each step record **PASS**, **FAIL**, or **NOT RUN**, actual speech or a summary, focus location, and reproduction steps. Include reviewer, date and time zone, Windows build, browser version, Narrator voice language, commit, and Job ID. Report when an action can be completed but essential information appears only visually. When a state is not announced automatically, record separately whether it can be found by reading the page. Keep NOT RUN until manual results exist. [Teammate review format](M4-teammate-review-checklist.md)
