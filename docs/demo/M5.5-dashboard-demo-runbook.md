# M5.5 controlled Dashboard demonstration

Use a fresh checkout of the M5.5 candidate. Both demos use controlled fixtures committed to the repository. The HTML fixture runs on an internal Docker network. The CSV fixture is submitted as text.

## Windows launcher

1. Start Docker Desktop with the Linux Engine. Run `Setup-Platform.bat` from the candidate folder to install locked npm dependencies and generate private settings.
2. In `.local/launcher.env`, set `LAUNCHER_FIXTURE=1` and `LOCAL_PROFILE_APPROVAL=1` for the trusted-local demo. If other services are using the defaults, choose unused values for `FRONTEND_PORT`, `API_PORT`, and `POSTGRES_PORT`. Preserve the generated credentials and project identity. Stop this checkout's launcher before editing its settings if it is already running.
3. Run `Start-Platform.bat`, wait for `[SUCCESS]`, and open the printed root URL if a browser does not open. The default Overview is `http://127.0.0.1:5197/`. A fresh **Overview** shows **No collections yet**. Check `http://127.0.0.1:58097/api/v1/health` using the configured API port and expect `{"status":"ok"}`.

See the [Windows setup guide](../setup/Windows-One-Click-Setup.md) for prerequisites, ownership, and subnet settings.

## Manual startup

With Docker Desktop running and Node/npm installed, open PowerShell from the repository root. Select unused host ports. The new Compose project gets fresh named volumes. These commands create a small local overlay so the build uses an image tag unique to this project and a bounded worker pool.

```powershell
$env:POSTGRES_USER = 'collection_test'
$env:POSTGRES_DB = 'collection_m55_test'
$env:POSTGRES_PASSWORD = [Guid]::NewGuid().ToString('N')
$env:POSTGRES_PORT = '55499'
$env:API_PORT = '58099'
$demoProject = 'collection-m3-test-m55-' + [Guid]::NewGuid().ToString('N').Substring(0,8)
$rcImage = "${demoProject}-backend:local"
New-Item -ItemType Directory -Force var/m5-local | Out-Null
$overlay = 'var/m5-local/compose.' + $demoProject + '.yaml'
@"
services:
  api:
    image: $rcImage
  worker:
    image: $rcImage
    command: ["python", "-m", "celery", "-A", "backend.queue.celery_app:app", "worker", "--loglevel=INFO", "--pool=prefork", "--concurrency=2", "--without-gossip", "--without-mingle"]
  dispatcher:
    image: $rcImage
  collection-fixture:
    image: $rcImage
"@ | Set-Content -Encoding utf8 $overlay
$composeArgs = @('-p',$demoProject,'-f','compose.yaml','-f','compose.fixture.yaml','-f',$overlay)
docker compose @composeArgs config --quiet
docker compose @composeArgs build api
docker compose @composeArgs up -d --wait postgres redis
docker compose @composeArgs run --rm --no-deps api python -m alembic upgrade head
docker compose @composeArgs up -d --wait
$apiBase = "http://127.0.0.1:$env:API_PORT/api/v1"
Invoke-RestMethod "$apiBase/health"
docker compose @composeArgs exec -T api python -m alembic current --check-heads
docker compose @composeArgs exec -T api python -m alembic check
```

Check each command succeeds. Retry health if the API is still starting. Expect `ok`, Alembic `0006 (head)`, and no drift. If Docker reports network pool exhaustion or overlap, inspect Docker networks and Windows/VPN routes. Add the following to the end of this project's overlay, replacing the two example subnets with unused private ranges, then repeat startup. Keep the first terminal open to retain the Compose variables.

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 10.249.109.0/24
  fixtures:
    ipam:
      config:
        - subnet: 10.249.110.0/24
```

In a second terminal from the repository root, set the actual API port and choose a free Vite port:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run build
$env:API_PROXY_TARGET = 'http://127.0.0.1:58099'
$env:LOCAL_PROFILE_APPROVAL = '1'
npm.cmd run dev -- --port 5208 --strictPort
```

Open [Overview](http://127.0.0.1:5208/) using the selected port. Profile approval uses the loopback Vite development proxy.

## Prepare the sources and profiles

In **Sources → Create source**, register the following with permission reference `FYP controlled fixture`.

| Source name | Adapter | Permitted input |
| --- | --- | --- |
| Controlled HTML fixture | Controlled web | Allowed origin `http://collection-fixture:8001` |
| Controlled CSV fixture | CSV | Allowed dataset ID `listings` |

Each Source starts **Pending**. A trusted operator explicitly authorizes each Source by its ID from the console. Use the manual `$apiBase` from above or set it to `http://127.0.0.1:58097/api/v1` with the configured launcher API port.

```powershell
$sourceId = '<Source ID from the console>'
Invoke-RestMethod -Method Patch -Uri "$apiBase/sources/$sourceId/authorization" -ContentType 'application/json' -Body '{"approval_status":"approved"}'
```

Repeat for the other Source. Reload and check that both are **Approved**. On each Source open **Create draft**. Use record type `listing`, identity field `key`, and keep all fields required.

| Source | Draft configuration | Validation input |
| --- | --- | --- |
| HTML | CSS item selector `#entries tr`. Field `title` uses selector `a` in Text mode. Field `key` uses selector `a` in Attribute mode with attribute `data-code`. | Select the allowed origin and enter document path `/table.html`. |
| CSV | Map `key` to `Key`, `title` to `Name`, and integer `count` to `Count`. | Select dataset `listings` and enter the clean sample below. |

```csv
Key,Name,Count
a0,Sample,1
```

Create each draft, enter its sample, choose **Preview** and then **Validate sample**. Once **Validation passed** appears, enter the operator label in **Approval review**, tick the confirmation, and choose **Approve version**. The version becomes read-only.

## Run both jobs and inspect results

1. Open **New Collection** from **Overview**. Choose **HTML pages**, the HTML Source and its approved version. Review the fields, select the permitted origin and enter `/table.html`. Choose **Start Collection**.
2. **Job Details** shows the Job ID and execution events. Expect **Succeeded** with 2 accepted, 0 invalid and 0 duplicates.
3. Repeat with **CSV datasets**, the CSV Source, its approved version and dataset `listings`. Paste the committed CSV fixture into **CSV content**. From the repository root use `Get-Content -Raw -Encoding utf8 -LiteralPath 'backend/tests/fixtures/m1/listings.csv' | Set-Clipboard`. Expect **Partial** with 2 accepted, 3 invalid and 1 duplicate.
4. Open **View job records**. The filter applies by Job ID on the server. Check the Job-scoped counts. **View quarantine** for CSV shows rows 5, 6, and 7. Duplicates appear as an aggregate count.
5. Toggle a column under **Fields to Display**. Open a record using its linked value and inspect the stored JSON with **View full payload**. Follow the record links to the Job, Source, Approved Profile version and Evidence Metadata. Return to Overview to see the latest jobs and records.
6. Switch **Theme** between System, Light and Dark. Reload a detail page to check persistence.

## Verify raw evidence bytes

Use the same `$apiBase` and replace the two Job IDs below. CSV evidence contains the UTF-8 text actually submitted through the browser. Textarea newline normalization can make its hash differ from the fixture file on disk. For the launcher, find the Compose project name in `.local/launcher.env` and keep that file private. For manual startup, use `$demoProject`.

```powershell
$project = '<Compose project name>'
$apiContainer = @(docker ps --filter "label=com.docker.compose.project=$project" --filter 'label=com.docker.compose.service=api' --format '{{.ID}}')
if ($apiContainer.Count -ne 1) { throw 'Expected one API container for the selected demo project.' }
foreach ($jobId in @('<HTML Job ID>','<CSV Job ID>')) {
    $evidence = Invoke-RestMethod "$apiBase/collection-jobs/$jobId/evidence"
    $evidenceHex = ([Guid]$evidence.evidence_id).ToString('N')
    $hashLine = docker exec $apiContainer[0] sha256sum "/data/evidence/$evidenceHex/input.bin"
    if ($LASTEXITCODE -ne 0 -or ($hashLine -split '\s+')[0] -cne $evidence.content_hash) {
        throw "Evidence hash mismatch for $jobId"
    }
    Write-Output "$jobId verified $($evidence.content_hash)"
}
```

Use `Stop-Platform.bat` for the launcher. For manual startup, stop Vite with Ctrl+C and run `docker compose @composeArgs stop` from the first terminal. Both retain the project volumes. The [M5 regression runbook](M5-core-demo-runbook.md) covers the broader suite and outage cases on disposable services. Use a separate Playwright output directory for each run.
